Tại Sao Lại Là KoreaQuest?

Giải quyết rào cản tiếp cận văn hóa và ngôn ngữ truyền thống bằng phương pháp Trò Chơi Hóa (Gamification).

Problem Statement
⚠️

Khó Khăn Thực Tế

Việc tự học lịch sử và văn hóa Hàn Quốc qua sách vở thường khô khan, nặng lý thuyết và thiếu bối cảnh thực tế sống động.

  • Thiếu động lực duy trì hàng ngày.
  • Thông tin du lịch rời rạc, khó nhớ.
  • Từ vựng tiếng Hàn dễ quên khi học chay.
💡

Giải Pháp Đột Phá

Ứng dụng triết lý Game-based Learning: mỗi địa điểm tham quan trở thành một chặng phiêu lưu với câu đố, văn hóa và ngôn ngữ.

  • Học gắn liền với không gian thực tế.
  • Thử thách trắc nghiệm phản hồi tức thì.
  • Giải thích nguồn gốc lịch sử sâu sắc.
🎯

Mục Tiêu MVP

Xây dựng thành công chu trình học tập khép kín và trực quan cho người dùng ngay trên nền tảng Flutter Web & Mobile.

  • Vòng lặp hoàn chỉnh: Check-in → Tổng kết.
  • Tích lũy XP, Level, Chuỗi ngày (Streak).
  • Sưu tập Dấu mộc Hộ chiếu điện tử.
격

Tech Stack & Cấu Trúc Mã Nguồn

Ứng dụng kiến trúc Feature-First hiện đại kết hợp Riverpod 3 và Supabase Cloud Backend.

Architecture
Frontend Framework Flutter Stable
Dart ^3.12 Material 3 Flutter Web Optimized
State & Routing Modern State
flutter_riverpod ^3.0.3 go_router ^17.0.1 intl ^0.20.2
Cloud Backend BaaS Cloud
Supabase Cloud (PostgreSQL) Row Level Security (RLS) Supabase Auth
// Cấu trúc Feature-First chuẩn mực
lib/
├── app/ # Router, Theme (Material 3), App config
├── core/ # Extensions, Responsive, Utils, Errors
├── design_system/# Color Tokens, Typography, Spacing, UI Components
├── shared/ # Shared Models, Repositories, Providers, Widgets
└── features/ # Phân chia theo module nghiệp vụ độc lập
    ├── auth/ # Đăng nhập & Đăng ký (Supabase Auth)
    ├── home/ # Dashboard, Streak, Cấp độ
    ├── explore/ # Bản đồ địa danh, Thẻ khám phá
    ├── journey/ # Check-in, Văn hóa, Từ vựng, Quiz
    ├── passport/ # Hộ chiếu điện tử, Bộ sưu tập Dấu mộc
    └── profile/ # Quản lý tài khoản cá nhân & Thành tựu

Quality Assurance
🌿

Quy Trình Git & Review Nhóm

Tuyệt đối không commit trực tiếp vào nhánh `main`. Mọi tính năng đều trải qua chu trình kiểm duyệt:

  • Mỗi thành viên làm việc trên nhánh Feature độc lập.
  • Pull Request có mô tả chi tiết và phạm vi ảnh hưởng.
  • Kiểm tra quyền sở hữu file (Team Ownership Matrix).
  • Cập nhật tài liệu kỹ thuật đồng bộ trước khi Merge.
🛡️

Bộ 4 Lệnh Kiểm Định Bắt Buộc

Mỗi thay đổi phải vượt qua toàn bộ 4 bước kiểm thử theo thứ tự trước khi bàn giao:

1. dart format . # Định dạng mã nguồn
2. flutter analyze # Kiểm tra 0 lỗi lint
3. flutter test # Chạy unit/widget test
4. flutter build web # Xác minh build web
동기
Nguyên tắc đồng bộ tài liệu Database: Mọi thay đổi SQL migration hay model Dart đều phải được ghi nhận cùng lúc trong tài liệu DATABASE_MODEL_DISCUSSION.md.
